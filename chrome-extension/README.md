# Studysis Chrome 扩展

## 概述

这个扩展负责 Studysis 的浏览器侧接入、页面数据采集和侧边栏展示，当前重点面向 B 站学习视频。

主要职责包括：

- 检测并绑定当前视频页面
- 尽早抓取官方字幕相关信息
- 在少量关键时机采集关键帧
- 把快照发送给本地后端
- 轮询后端会话状态并刷新侧边栏
- 支持点击章节时间点回跳视频

## 在 Chrome 中加载

1. 打开 `chrome://extensions/`
2. 开启开发者模式
3. 点击“加载已解压的扩展程序”
4. 选择 `chrome-extension/` 目录

如果修改了 `manifest.json` 或脚本文件，需要重新加载扩展。

## 当前工作方式

扩展当前已经不是早期的“高频轮询 + 高频上报”方案，而是事件驱动为主：

1. 页面初始化
2. 绑定视频元素
3. 生成或复用 `session_id`
4. 收集页面元数据、字幕轨道和缓冲信息
5. 在关键事件上发送快照到后端
6. 轮询后端 session 结果并刷新侧边栏

## 快照上报

默认后端接口：

```text
POST http://127.0.0.1:8000/api/v1/collect/segment
```

扩展发送的 source 信息通常包括：

- 页面标题、URL、host
- 页面简介和上下文文本
- 官方字幕轨道
- 字幕预览
- 缓冲区间
- 关键帧

## 当前关键帧采集策略

关键帧不会在每次轮询都抓，而是只在这些事件上尝试采集：

- `video-attached`
- `playback-start`
- `seeked`
- `paused`
- `playback-timer`（定时器触发）
- `subtitle-schedule`（字幕调度触发）

并且还有限制条件：

- 单个 session 最多发送 15 张图
- 同一触发类型按 10 秒时间桶去重
- 除 `seeked` 之外，默认要求与上一张图至少间隔 45 秒；`seeked` 至少间隔 30 秒
- 视频没有足够 `readyState` 或当前帧尺寸不可用时不会截图

所以当前视觉增强效果高度依赖真实播放行为。想让后续章节也拿到板书识别，通常需要在对应章节附近实际播放、暂停或跳转。

此外，扩展还会根据字幕段边界计算关键帧采集调度表（`subtitle-schedule`），在字幕段范围内均匀采样关键帧时间点，以提高章节视觉增强的命中率。

## 侧边栏更新逻辑

侧边栏当前展示是“先占位，后补全”的：

- 先展示快速加载态或预览态
- 后端 outline 就绪后，先出现总览
- 章节内容随后逐步补全
- 如果后面又采到新关键帧，章节区可能会增量刷新

当前前端还会跟踪后端返回的 `analysis_request_version`，用于识别同一个 session 的分析版本变化。

侧边栏还支持导出功能：Word (.docx) 下载和打印友好 HTML 页面（可直接打印或存为 PDF）。

## 与后端的配合关系

扩展负责“采”和“显示”，真正的分析逻辑在后端：

- 扩展不做 OCR 或板书理解
- 扩展只负责提供字幕与关键帧原料
- 后端负责文本总结、章节详解和视觉增强

因此当前前端是否能看到板书提取结果，核心取决于两点：

- 对应章节附近是否采到了合适关键帧
- 后端视觉模型是否成功完成该章节增强

## B 站相关说明

当前代码主要围绕 B 站学习视频做优化：

- `page-hook.js` 运行在页面上下文
- `content.js` 负责接收和标准化字幕/视频信息
- 官方字幕轨道与调试数据会传给后端落盘

## 权限说明

当前扩展使用了这些权限：

- `storage`
- `tabs`
- `sidePanel`
- 较宽的 host permissions，用于本地后端访问和页面接入

如果后续准备公开发布，请重新检查 `manifest.json` 中的权限范围并尽量收紧。
